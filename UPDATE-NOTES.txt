DEPLOYMENT
- Run the updated supabase-setup.sql in Supabase SQL Editor.
- Redeploy: supabase functions deploy send-confirmation --no-verify-jwt
- Keep the existing BREVO_API_KEY, SENDER_EMAIL, SENDER_NAME and WEBHOOK_SECRET secrets.
- Keep the Database Webhook header x-webhook-secret unchanged.
- Test with a new registration. Existing registrations will not automatically receive PDFs.
- The signed PDF download link expires after 30 days.

IMPORTANT
The registration PDF is personal data. The Storage bucket is intentionally PRIVATE; do not switch
it to public. The Edge Function uses the Supabase service-role key to upload and sign each file.

WHAT YOU MUST DO IN VS CODE BEFORE THE SITE GOES LIVE
A. Extract this ZIP and open the INFINORA-REGI folder in VS Code. Make sure the folder you open contains index.html and the supabase folder.
B. Replace the files in your GitHub Pages publishing root with the contents of this folder (do not upload the folder as an extra nested folder). Commit and wait for the Pages deployment to finish.
C. In the VS Code terminal, from the INFINORA-REGI project root, run:
   supabase --version
   supabase login
   supabase link --project-ref vinxjahrdrahhzweyomm
   supabase functions deploy send-confirmation --no-verify-jwt
   The function has its own x-webhook-secret check, so keep verify_jwt disabled as it is now. Do not change the existing BREVO_API_KEY, SENDER_EMAIL, SENDER_NAME or WEBHOOK_SECRET secrets. Never put the service-role key in website JavaScript.
D. Check Supabase > Edge Functions > send-confirmation and confirm the new deployment is active. Keep the existing Database Webhook and its x-webhook-secret header unchanged.
E. Test with a new team registration using an email address you control. Confirm the email arrives, the PDF downloads as two pages, page 2 lists every participant in separate rows, and the new registration appears in the admin dashboard without refreshing.
